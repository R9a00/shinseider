# ブラウザー保存の仕様

対象: GitHub Issues #1 / #2 / #3。申請文とフカボリは `static/project-store.js` を共用する。

- 既存の `shinseider_project` キー、version 1 の JSON、控えファイルの形式を維持する。
- 保存完了後にのみ「自動保存済み」と表示する。容量超過・アクセス拒否等は未保存と表示し、画面上の入力を維持する。処理中・未保存の離脱ではブラウザーの確認を要求する。
- 各タブで編集したフィールドのみ最新の保存データへ反映する。異なるフィールドは併存する。同じフィールドが読み込み時から変更されている場合は、同じ値の保存を除いて競合とし、保存全体を止める。
- 読み込み・比較・書き込みは Web Locks で直列化する。HTTPSまたはlocalhostで利用する。Web Locks非対応環境では安全のため自動保存せず、控え保存を案内する。
- 他タブの変更で編集中の入力を自動的に差し替えない。再読込で最新の内容を見る。競合時は先に控えを保存してから再読込し、内容を比較する。
- 控えには他タブの保存済み項目と、このタブの未保存の変更を含める。競合した項目は、このタブで作った文章を控えに残す。控え読込も形式検査と同じ競合検査を通す。
- 保存データが壊れている場合は無断で初期化・上書きしない。
- 診断の `shinseider_check` は最後に明示的に判定した回答を保存する。保存に失敗しても判定自体は表示し、結果が未保存であることを伝える。

公開切替時に既に開いていた旧版タブの保存処理はこの仕組みに参加しない。更新後は旧版タブの入力を控えに残して閉じ、新しいページを読み込むこと。Web Locksは旧コードによる書き込みを防ぐものではない。

カレンダー（Issue #4）は静的ICSのまま、ビルド日時と「その時点で終了していない日程」を収録範囲として説明する。診断の任意質問はQ4（Issue #5）。

## 検証

`node --test site/tests/*.test.cjs` は失敗、再試行、同時保存、競合、控えの内容、破損データを検証する。`python -m unittest discover -s site/tests -p 'test_*.py'` はICSの日時境界を検証する。

`python site/test_site.py` は実際に生成した12ページをlocalhostで配信し、隔離したChromiumで必須質問、保存失敗、複数タブ、控えの往復、進捗を検証する。日時を固定し、外部AI・アクセス解析へのリクエストは遮断する。GitHub Actionsでも同じコマンドを実行する。
