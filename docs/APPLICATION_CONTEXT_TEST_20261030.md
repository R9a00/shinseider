# 調査・応募書類作成・品質チェックの実装と検査

## 対象と結論

EXP PSで選択されたattg内の公開正本 `shinseider-next/shinseider-poc` を対象とした。起動時スナップショットではなくgitを再観測し、main 5822d71を基準に隔離worktreeで作業。元の未コミット作業は保全した。

公式PDFと経験者記事を使う調査・材料・フォーマットでの作成・完成稿点検の4段階を追加した。入力の保存、原本付き引継ぎ、JSON再読込み、MCP保存と再開、古い点検結果の判別を検査した。検索・文章作成・意味的評価はユーザーが利用するAIが行う方式である。

## 根拠の選別

採用した資料・日付・用途は `data/application_support.yaml` に記載。公式PDFを形式・6記載項目・5評価の基準とし、出場者本人のnote、受賞者と支援者の対談、受賞者インタビュー、公式媒体の挑戦記録を準備の参考とした。経験談を因果的な勝利条件にしない。

「審査基準は非公表」とする記事は公式PDFの明示と食い違うため、その主張を採用しなかった。大会回次・受賞者の記述が整合しない記事も採用対象から除外。有料noteの有料部分は取得していない。事業固有の市場・競合の調査を済ませたとは扱わず、利用者のAIが検索して出典を追加する。

## 実装・影響先

- 新しい `application.html` と共通文脈JSON。公式6項目の本文・根拠・宿題・図表候補、出典の状態を別々に保存。
- PDF/PPTX/DOCX/TXT/MDをブラウザー内とMCPで抽出。PPTXは実際のスライド関係の順に読む。画像・図・ページ配置の自動評価はしない。
- AIへ指示文・文脈・原本をZIPで渡す。公式のページ割付を推測で固定しない。MCPは14 tools / 5 prompts / 6 resources。
- 旧entry/fukaboriの控えにも追加データを保持。現行データの変更と正本の改訂を点検結果のbindingに反映する。
- 版固定のPDF.js/fflateを同梱。MCPにpypdf依存を追加。既存利用者は更新と再接続が必要。

## 自動検査

- Node 12件：既存保存・競合・異常データ保護、追加文脈、点検対象の変化と指示生成。
- Python 11件：既存判定・日付・指示、STDIO実通信、再起動後の本文/点検結果一致、境界外アクセス拒否、古いbindingの拒否、文書抽出、ブラウザー/Pythonの指示とハッシュ一致。
- ブラウザーで実際にPPTX・PDFを読み込み、原本入りZIPを展開してバイト一致を確認。JSONの再取込み、不正JSONの非破壊拒否、古い点検結果表示、再選択要求、旧画面からの控え保存を検査。
- 13ページの375px/1280px表示で横あふれ・JavaScript例外なし。既存の診断・期限・インポート・コピー・保存失敗・複数タブ・バックアップの回帰検査も合格。
- 原本フォーマットのパーサー試験には最小XMLの試験PPTX/DOCXを使用。正式なOffice編集互換性の検証ではない。PDFは文字あり・文字抽出不可のページを含む。

## MCPを使った成果物の検査

[試験入力](application-context-20261030/scenario.md)は完全な架空ケース。8ページの[試験フォーマット](application-context-20261030/template.pdf)と、わざと誤りを含む[完成稿](application-context-20261030/draft.pdf)をMCPで抽出し、[文脈JSON](application-context-20261030/context.json)に保存した。

MCPから実際に得た[点検指示](application-context-20261030/review-instructions.md)を本セッションのAIが読み、固定入力とPDFの引用を照合して[レビュー](application-context-20261030/review.md)を作成した。PDF全8ページをPopplerで描画して目視確認。月年換算漏れ、関心を契約実績へ変えた誤記、未調査からの競合不在の断定を指摘し、修正文を示した。6項目と5評価の不足も個別に記録した。

レビューを `application_review_save` で記録し、別プロセスの再接続で内容が一致した。[再開後の文脈](application-context-20261030/resumed-context.json)、[MCP要求・応答](application-context-20261030/mcp-calls.jsonl)を保存した。このケースは既知の誤りを同じAIが点検しており、独立評価・盲検試験・未知の誤りの検出率測定ではない。

## 未確認・残る範囲

- 実際にエントリー後に届くフォーマット原本のページ別指定は未入手。試験PDFは公式サンプルではない。
- 本人の市場・競合・顧客・採算の事実確認、実際の応募書類の作成と提出、受賞可能性はこの検査の対象外。
- AIアプリによって検索、ZIP読込み、PowerPoint編集・PDF描画の可否が異なる。使えない機能は未実施と明示する指示を付けた。原本を読まずに視覚確認済みとすることは認めない。
- ネットの更新・記事の真偽を自動追跡しない。確認日を明記し、調査の開始時に公式と出典を再確認する。
