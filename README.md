# シンセイダー — アトツギのための準備室

https://shinseider.onrender.com で公開している静的サイトのソースです。
中小企業庁が任命するアトツギ甲子園アンバサダーが個人で運営する、非公式・無償の申請準備ツールです。掲載情報には出典と確認日を付記しています。正確な情報は必ず[アトツギ甲子園公式](https://atotsugi-koshien.go.jp/)・各補助金の公募要領原文をご確認ください。

## 構成

- `site/build.py` — `data/` のYAMLとテンプレートから静的サイトを `site/dist/` に生成
- `data/` — 掲載情報の元データ（出典・確認日つき）
- `render.yaml` — Render Static Site のビルド定義

## ビルド

```bash
pip install pyyaml jinja2
python3 site/build.py
```

旧システム（React + FastAPI版）のコードは `archive/v1` ブランチにあります。

## 問い合わせ導線

「相談できる人」ページの紹介文直後に「問い合わせ先」リンクを置き、運営者ページの `about.html#contact` に直接移動します。連絡先は同ページに掲載するX・Facebook・会社サイトです。
直接移動した場合も宛先がわかるよう、見出しに「運営者へのお問い合わせ」、本文に運営者名を明記します。

## 締切が近い時期の道筋

`data/koshien_entry.yaml` の `pace.late_plans` が終盤の道筋の正本です。画面（`site/templates/_pace.html`）とMCP（`get_pace_plan`）が同じ項目を同じ選び方で使います。今日の日付（日本時間の暦日）が `late_from` 以降のとき、`until` が今日以降である最初の項目を表示します。それより前の時期は従来の逆算プランです。

順番は「先にエントリー、応募書類は連休（11/21〜23）で」です。根拠は、サンプルフォーマットと案内がエントリー後に届くことと、応募書類が受付期間内なら出し直せること（いずれも公式サイト、2026-11-12確認）。連休前の登録は本ツールの推奨で、公式締切ではありません。フォーマットが届くまでの時間は公式に明記がないため、断定する文言は書きません。

道筋ページの「先に知っておくと、時間が浮くこと」は同じファイルの `late_start` が正本です。公式の記載の要約で、出典と確認日を付けます。エントリー者数のように日々変わる値は、本文に基準日を入れます。

申請書の準備ページの「締切が近いときは、応募書類の文面まで一気につくる」は、`sprint_prompt_template` と `preparation.py` の `sprint_prompt` で生成します。公式6項目を直接聞き、ページの割付は創作させません。MCPには未追加です。

指示文には、中小企業診断士の視点（強みの根拠・収益の積算・実現可能性・リスク）と、主催者のねらいからの点検を入れています。ねらいは `official_preparation.purpose` が正本で、経済産業省の報道発表（2026-07-15）の記載の要約です（早期の事業承継の促進に向けた後継者の育成。戦略立案能力・発信力・実行力）。「診断士の視点」は必ず「資格者による診断ではない」と対で書きます。ねらいは公式の評価項目そのものではないため、公式5評価と区別して示します。道筋ページの相談窓口は `late_start.support` が正本で、各公式サイトの記載の要約です。

`sprint_prompt_template` は、2026-11-12に架空の会社で最後まで会話させる試験を行い、その結果で直しています（質問は15問まで、公式6項目すべてに最低1問、必ず聞く4つは別の質問で）。方法・結果・限界は [docs/DOCUMENT_PROMPT_DRYRUN_20261112.md](docs/DOCUMENT_PROMPT_DRYRUN_20261112.md) にあります。答える側もAIによる模擬で、人が答えた場合の所要時間、Claude以外のAIでの動作、ボタンから指示文入りで開く動作は未確認です。

トップページは、エントリー締切まで20日以内の時期だけ、冒頭に道筋への案内を出します。エントリー締切後から書類提出締切までは、書類提出の案内に切り替わります。

来季は `late_from`・`late_plans`・`late_start` を日程に合わせて書き換えます。ビルドは、`late_plans` が締切当日まで途切れず昇順に並ぶことを検査します。

## 応募書類への使い方

`data/koshien_entry.yaml` の `official_preparation` を公式6記載項目・5評価・提出形式の正本とし、画面とMCPで共有します。既存の5テーマは材料整理用で、保存する項目IDは変更しません。`preparation.py` はインタビュー・予行審査・深掘り章の指示文を共通生成します。公式要項と独自の整理目安を区別し、利用者の実行済みの行動と将来計画を混同しません。

参考パッケージの採用内容・既存修正との差・検証範囲は[追加修正記録](docs/PACKAGE_REVIEW_20261030.md)に記載しています。Pythonの検査には、一時フォルダ内のMCPサーバーとのSTDIO通信と再起動後の記録保持も含まれます。

## 調査から応募書類作成・品質チェックまで

[作成・点検ページ](https://shinseider.onrender.com/application.html)で、公式6項目の本文・根拠・宿題・図表案を保存します。出典付きの経験者の知見と、事業固有の追加調査指示を使い、提出フォーマット・完成稿をローカルで読み込み、普段のAIへ原本入りの一式を渡せます。検索・作成・内容評価は接続先AIが行います。材料やファイルを変更すると、以前の点検結果は再点検が必要な状態になります。

設計とデータ契約は [APPLICATION_CONTEXT.md](docs/APPLICATION_CONTEXT.md)、検査範囲と成果物は [APPLICATION_CONTEXT_TEST_20261030.md](docs/APPLICATION_CONTEXT_TEST_20261030.md) を参照してください。MCPでも同じJSONを保存・再開できます。既存MCP利用者はコードと依存パッケージを更新して再接続してください。
